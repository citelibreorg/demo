= Cite Libre - Demo

image:https://img.shields.io/github/license/citelibreorg/demo.svg[License]

**CiteLibre** is the software suite provided by Lutece to help you implement a wide range of digital services ready for deployment with your brand image.
The services (RendezVous, Service'EZ, Particip'EZ) are developed on the Lutece platform, pre-assembled and containerized for easy deployment, and 100% open source.

This repository holds the **Docker Compose** stack to run the CiteLibre services locally, plus the Cypress end-to-end tests.

== 🗂️ Repositories

CiteLibre is split into three repositories:

[cols="1,3"]
|===
| Repository | Content

| https://github.com/citelibreorg/packaging[packaging]
| Maven assembly of each service (Lutece core + plugins + configuration) and Docker image build (Jib)

| https://github.com/citelibreorg/demo[demo] (this one)
| Docker Compose stack to run the services locally: shared platform (Keycloak, Matomo, Solr, Elasticsearch/Kibana, ...), one compose file per service, Cypress e2e tests

| https://github.com/citelibreorg/ops[ops]
| Kubernetes deployment descriptors (Yupiik Bundlebee) and Minikube helper scripts
|===

== 📁 Layout

[cols="1,3"]
|===
| Path | Content

| `citelibre.sh`, `citelibre.cmd` (+ `citelibre.ps1`)
| Demo launcher for Linux / macOS and Windows (see <<quick-start>>)

| `citelibre-platform/`
| Shared third party components: MariaDB, Keycloak, Elasticsearch, Kibana, Solr, Matomo, Adminer, Mailpit and an httpd portal on port 80

| `citelibre-common/sql/init_db.sh`
| Database bootstrap script shared by every compose file

| `citelibre-rendezvous/`, `citelibre-serviceez/`, `citelibre-participez/`
| One service each: `docker-compose.yml`, `.env` and database init `sql/`

| `tests/`
| Cypress end-to-end tests (see `tests/readme.adoc`)
|===

All compose files take their variables from the `.env` file next to them. These are local demo credentials, never put real secrets there.

== 🚀 Quick start

The only prerequisite is https://docs.docker.com/get-docker/[Docker] (Docker Desktop on Windows and macOS), started, with about 8 GB of memory available (4 GB with `--lite`). Port 80 must be free.

. Download this repository: `git clone https://github.com/citelibreorg/demo.git`, or *Code > Download ZIP* on GitHub, then unzip it.
. Start the demo:
** Windows: double-click `citelibre.cmd`
** Linux, macOS: `./citelibre.sh`
. Wait for the `CiteLibre rendezvous is ready` message (a few minutes the first time, the images are downloaded): the browser opens the portal at http://localhost/.

[cols="1,2,2"]
|===
| What | URL | Account

| Front office
| http://localhost/citelibre-rendezvous/jsp/site/Portal.jsp
| `test@citelibre.org` / `citelibre`

| Back office
| http://localhost/citelibre-rendezvous/jsp/admin/AdminMenu.jsp
| `admin@citelibre.org` / `citelibre`

| Mails sent by the services
| http://localhost/mailpit/
|
|===

The launcher takes a command, an application and options (`citelibre.cmd` takes the same arguments as `./citelibre.sh`):

[source,bash]
----
./citelibre.sh                           # same as: ./citelibre.sh start rendezvous
./citelibre.sh start rendezvous --lite   # light platform: no Elasticsearch, Kibana, Solr, Matomo, Adminer
./citelibre.sh start rendezvous --version 2.0.2   # another image version, local or on Docker Hub
./citelibre.sh status                    # list the CiteLibre containers
./citelibre.sh logs rendezvous           # follow the Lutece logs (application.log, error.log)
./citelibre.sh stop                      # stop everything, data is kept for the next start
./citelibre.sh reset                     # remove everything, the next start begins from scratch
----

The launcher uses the local image when it exists (built from the `packaging` repository), otherwise it pulls it from Docker Hub. It checks Docker and port 80, starts the platform then the application in the right order, and waits until they answer.

The demo comes with ready-made data (appointments, users, emails) and a walkthrough to present it: see <<demo-data>>.

=== RendezVous: appointments

Three appointment forms, opened from two months ago to one year ahead:

[cols="2,2,1,1"]
|===
| Form | Opening hours | Slots | Places per slot

| Passeport et carte nationale d'identité (`ID…` references)
| Monday to Friday, 9:00-12:00 and 13:40-17:00
| 20 min
| 1

| Permanence logement (`LOG…`)
| Tuesday and Thursday, 14:00-17:00
| 30 min
| 1

| Inscriptions scolaires et périscolaires (`SCO…`)
| Monday, Wednesday and Friday, 8:30-12:00
| 30 min
| 2
|===

About forty bookings by fictitious users (`@example.org` emails) fill part of the two coming weeks, with free slots left. A few are in the past (honoured or missed) and one is cancelled. The dates are computed from the day the database is created, so the calendar always looks current.

The *Rendez-vous* workflow follows each appointment and emails the user at each step:

[cols="1,2,2"]
|===
| Action | Triggered by | Email to the user

| Confirmation
| a booking (automatic)
| confirmation, with the reference and a cancel link

| Rendez-vous honoré
| an agent, in the back office
| thank you

| Usager absent
| an agent, in the back office
| missed appointment, invitation to book again

| Annuler le rendez-vous
| an agent, or the cancel link of the confirmation email
| cancellation, the slot is freed
|===

A walkthrough to show the whole cycle:

. *Book as a user*: open the forms list http://localhost/citelibre-rendezvous/jsp/site/Portal.jsp?page=appointment&view=getViewFormList (accept the cookie banner to see the calendar), choose a form, a free slot, then enter a name and any email address.
. *Read the confirmation* in Mailpit: reference, date, cancel link.
. *Manage as an agent*: in the back office, menu *Gestion des rendez-vous*, open a form to see its bookings by calendar, by filter or by day; the new booking is there, in the *À venir* state.
. *Process an appointment*: run *Rendez-vous honoré* or *Usager absent* on a booking: its state changes and the user receives an email in Mailpit.
. *Cancel as a user*: follow the cancel link of the confirmation email: the cancellation email arrives and the slot is free again in the calendar.

==== Changing the demo data set

The RendezVous demo data are loaded by `citelibre-rendezvous/sql/03-demo-appointments.sql`, run after the database dump (`00-init.sql`) when the database is created. This SQL file is *generated* by the Python script next to it, `citelibre-rendezvous/sql/03-demo-appointments.py`: do not edit the SQL by hand, edit the script and regenerate.

Why a script: the SQL holds about 370 lines, mostly mechanical (one opening time slot per form, day and slot duration, booked slots whose taken and remaining places must match their bookings, fictitious emails and phone numbers derived from the names). The script only holds the readable data and checks it before writing the SQL:

[cols="1,3"]
|===
| Variable | Content

| `FORMS`
| the appointment forms: title, reference prefix, description, opening days and hours, lunch break, slot duration, places per slot, color

| `BOOKINGS`
| the bookings, one tuple per booking: `(form, weekday, week, time, first name, last name, state)`. `week` is relative to the import day: `1` is the next occurrence of that weekday, `2` the one after, `-1` the last one before today. For instance `(1, MON, 1, '09:00', 'Claire', 'Martin', U)` is "next Monday at 9:00, upcoming". States: `U` upcoming, `H` honoured, `A` absent, `C` cancelled

| `MAILS`
| subject and message of the emails sent by the workflow actions. The messages are FreeMarker templates: `${firstName}`, `${lastName}`, `${date_appointment}`, `${time_appointment}`, `${reference}`, `${url_cancel}`...
|===

The script refuses a booking outside the opening days or hours, during the break, not aligned on a slot, or exceeding the places of its slot. The dates are not written in the SQL: MariaDB computes them from `CURDATE()` at import time, so the data set stays current whatever the day the demo is (re)initialized.

To apply a change (Python 3, no dependency):

[source,bash]
----
cd citelibre-rendezvous/sql
python3 03-demo-appointments.py 03-demo-appointments.sql
cd ../..
./citelibre.sh reset && ./citelibre.sh
----

Commit both the script and the regenerated SQL. These are demo data only: the production deployment (`ops` repository) starts empty and must not get them.

== 🔧 Docker Compose

The launcher only wraps the following Docker Compose commands, which can also be run by hand.

=== CiteLibre backbone
First of all, you need to run the common platform that holds third party components such as Keycloak, Kibana/ES, Matomo, Solr, etc...
It also creates the `citelibre-network` docker network used by every service.

[source,bash]
----
docker compose -f citelibre-platform/docker-compose.yml up [-d]
----

To save memory, start only the services the applications need (MariaDB, Keycloak, httpd and Mailpit): the applications still work, without search and analytics.

[source,bash]
----
docker compose -f citelibre-platform/docker-compose.yml up -d mariadb init-keycloak-db keycloak httpd mailpit
----

You can then access the following service interfaces

- **Matomo** is used to store and display web and app analytics (http://localhost/matomo: admin/adminadmin)
- **Adminer** to easily access and interact with the application data (http://localhost/adminer?server=rendezvous-db&username=citelibre&db=rendezvous password: rdv)
- **Keycloak** to manage front-end and back-end authentication and single sign-on (http://localhost/keycloak/admin: admin/admin1234)
- **Elasticsearch** to store all business-related app data (http://localhost/elasticsearch)
- **Kibana** to display business analytics dashboards (http://localhost/kibana: lutece/RKOmBI1sWaa*SFm1gx*H)
- **Mailpit** catches every email sent by the services (http://localhost/mailpit)

Or simply go to http://localhost/ that will show a Portal to all deployed applications.

=== Launch a CiteLibre RendezVous instance

The platform must be up first: the service compose files declare `citelibre-network` as an external network.

[source,bash]
----
docker compose -f citelibre-rendezvous/docker-compose.yml up [-d]
----

- Back office at http://localhost/citelibre-rendezvous/jsp/admin/AdminMenu.jsp : admin@citelibre.org/citelibre
- Front office at http://localhost/citelibre-rendezvous/jsp/site/Portal.jsp : test@citelibre.org/citelibre

The ready-made demo data are described in <<demo-data>>.

The `citelibre/packaging-rendezvous` image is pulled from Docker Hub (published by the `packaging` release workflow), unless it was built locally from the https://github.com/citelibreorg/packaging[packaging] repository:

[source,bash]
----
# in the packaging repository
mvn clean package -Passembly,rendezvous,docker
----

The local build produces the same image name as Docker Hub (`citelibre/packaging-rendezvous:<version>`), and Docker Compose only pulls an image that is missing locally: a locally built image with the same version is used as is.

The image version used is `CITELIBRE_IMAGE_VERSION` in `citelibre-rendezvous/.env`. To run another version built locally (the profile's `citelibre.packaging.version` in the `packaging` pom), override it from the shell, which takes precedence over the `.env` file:

[source,bash]
----
CITELIBRE_IMAGE_VERSION=2.0.2 docker compose -f citelibre-rendezvous/docker-compose.yml up [-d]
----

The databases are created on the first start only: `stop` / `start` (or `up` again) keeps the data, `down` removes it. The Lutece logs are in the `rendezvous-logs` named volume (`CITELIBRE_DOCKER_VOLUME_PATH` in the `.env`, which also accepts an absolute host path).
